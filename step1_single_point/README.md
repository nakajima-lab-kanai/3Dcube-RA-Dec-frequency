# 段階1:1ビーム・1点観測の FMLO シミュレーション

野辺山45m望遠鏡での OTF + FMLO 観測を想定した大気雑音除去の検討のうち、段階1(1ビームで空の1点を見続ける場合)のシミュレーションです。
段階2(1ビームでスキャン)・段階3(マルチビーム)で再利用できるよう、処理を `fmlo_sim/` のモジュールに分けています。

「要確認」と書いた値は根拠を確認できていない仮の値です。結果を解釈する前に確認してください。

## 実行方法

```bash
pip install -r ../requirements.txt
cd step1_single_point

python run_step1.py                 # 既定設定で実行。outputs/step1/ に図と評価値を出力
```

設定は `config/default.yaml` を編集するか、`--half-width-ch` や `--zigzag-step-ch`、`--atmosphere-model`、または `--set` で一時的に上書きします。

```bash
python run_step1.py --half-width-ch 150 --zigzag-step-ch 10 --atmosphere-model laminar
python run_step1.py --outdir outputs/offset50 --set noise.atmosphere.offset_k=50 --set removal.n_components=2
python run_step1.py --set modulation.pattern=random
python run_step1.py --set source.line_fwhm_kms=100 --half-width-ch 300
```

同じ設定ファイル(同じ `seed`)なら結果は再現します。乱数は成分ごと(変調・熱雑音・大気)に独立なので、ある成分の設定を変えても他の成分の乱数列は変わりません。

## 処理の流れ

| 手順 | 内容 | モジュール |
|---|---|---|
| 1 | 正解キューブ(RA × Dec × 周波数、単位 K)を作る。ガウシアンのボール1つ | `cube.py` |
| 2 | 指定ピクセル(既定は天体中心)のスペクトルを取り出す | `cube.py` |
| 3 | FMLO 変調:各時刻で観測窓をずらし、広い周波数グリッドから窓を切り出す | `modulation.py` |
| 4 | 雑音を成分ごとに作って足す(熱雑音、大気) | `noise.py` |
| 5 | PCA で上位成分を除去する | `removal.py` |
| 6 | 記録したシフト量で復調し、時間平均して復元スペクトルを得る | `modulation.py` |
| 7 | 正解と比べて評価値を出す | `evaluation.py` |
| 8 | 各段階の図を出す | `plotting.py` |

手順 1〜4 は `pipeline.simulate()`、5〜7 は `pipeline.reduce()` にまとめてあります。設定の読み込みは `config.py`、単位変換は `units.py` です。

### モデルの定義と仮定

- **周波数グリッド**:キューブの周波数軸は分光計の帯域より広く、両側に「変調の半幅 + 余白」チャンネルずつ余分に取ります。チャンネル幅は分光計と同じなので、窓の切り出しは整数チャンネルのスライスです。`np.roll` は使っておらず、窓がグリッドからはみ出す設定はエラーになります。
- **シフト量の符号**:正のシフトは窓が高周波側へ動くことを表します。
- **速度と周波数**:Δν = ν Δv / c(radio 定義)。輝線幅は FWHM、天体の空間サイズは σ で指定します(変数名で区別、変換は `units.fwhm_to_sigma` / `sigma_to_fwhm`)。
- **ビーム**:望遠鏡ビームの畳み込みは入れていません。キューブのピクセル値をそのまま観測値とします。
- **熱雑音**:ΔT = Tsys / sqrt(Δν_ch × Δt) の標準偏差で、各時刻・各チャンネル独立に生成します。OFF 点の差し引きがない前提で、√2 の係数は付けていません。
- **大気**:`(offset_k + a(t)) × s(ν)`。a(t) は全チャンネル共通の時間変動で、パワースペクトルが f^(-α) に従う有色雑音です(平均 0、標準偏差 `rms_k`)。s(ν) は **空の周波数** の関数 `1 + slope_frac × (ν − ν_c) / (B/2)` で、天体信号と同じ窓で切り出します。したがって窓をずらすと、大気の傾きも一緒にチャンネル上を動きます。
- **復調後の評価範囲**:全時刻で観測された周波数範囲(ヒット数 = 時間サンプル数)だけで評価します。
- **輝線のない領域**:輝線中心から ±(`line_free_n_fwhm` × FWHM) の外側です。積分強度はその内側で積分します。

### 雑音成分の差し替え・追加

`NoiseComponents` に `(n_time, n_channels)` の配列を名前付きで `add()` します。

- 大気の時間変動を外部の時系列(将来は Gato)に替える場合は、`noise.atmosphere_noise()` の `timeseries_k` にその時系列を渡します。
- チャンネル(IF)側に固定された成分(装置由来の雑音)は今回実装していません。追加する場合は、窓で切り出さずに `(n_time, n_channels)` の配列をそのまま `add("instrument", tod)` します。

## PCA の平均の扱い

`sklearn.decomposition.PCA` は必ず各チャンネルの時間平均を引くため、ここでは numpy の SVD で実装し、`removal.mean_mode` で明示的に選びます。

| `mean_mode` | 処理 |
|---|---|
| `none`(**既定として採用**) | 平均を引かずに SVD し、上位成分を除去する |
| `channel_mean` | 各チャンネルの時間平均を引いてから SVD し、上位成分を除去する。引いた平均は戻さない(sklearn の `X - inverse_transform(transform(X))` と同じ。テストで一致を確認) |

`run_step1.py` は設定の `mean_mode` にかかわらず、同じ観測データに対して `none`、`channel_mean`、`no_pca`(PCA も平均除去もせず復調だけ)の3通りを評価し、`metrics.json` と `metrics_comparison.csv` に並べて出力します。図 5 は設定で選んだモード、図 6・7 は両モードを重ねて描きます。

### 既定設定での結果(seed = 20261005、除去成分数 1)

熱雑音だけを時間平均した場合の期待 RMS は 0.037 K です。

| 処理 | 輝線なし領域の残差 RMS [K] | ピーク比 | 積分強度比 |
|---|---|---|---|
| `none` | 0.039 | 0.98 | 0.93 |
| `channel_mean` | 0.043 | 0.83 | 0.43 |
| `no_pca` | 0.037 | 1.00 | 0.98 |

- `channel_mean` は輝線を大きく削ります。変調でならされた輝線の時間平均(幅が変調幅程度の台地)が平均スペクトルとして引かれ、復調後に輝線の両側が負にへこむためです。
- `none` でも積分強度が約 7 % 減ります。第1成分(ほぼ平らなスペクトル)が、各時刻の輝線の帯域平均を大気の変動と区別できずに吸収するためです。
- **この設定では `no_pca` が最も正解に近くなります。** 大気の時間変動 a(t) は平均がちょうど 0 になるよう作っているので、1点を見続けて時間平均するだけで消えるためです。PCA の効果は時間平均後のスペクトルではなく、時間方向のパワースペクトル(図 7)に現れます。定数オフセットがある場合は次節のとおり状況が変わります。
- ピーク比は1チャンネルの値の比なので、熱雑音による ±4 % 程度のばらつきを含みます。

### 大気の定数オフセットと平均モードの組み合わせ

`noise.atmosphere.offset_k` を 0 以外にしても最後まで動きます(テストあり)。既定設定から `offset_k` と除去成分数だけを変えた結果です。

| `offset_k` [K] | 成分数 | 処理 | 残差 RMS [K] | ピーク比 | 積分強度比 |
|---|---|---|---|---|---|
| 0 | 1 | `none` | 0.039 | 0.98 | 0.93 |
| 0 | 1 | `channel_mean` | 0.043 | 0.83 | 0.43 |
| 0 | 2 | `none` | 0.041 | 0.83 | 0.60 |
| 0 | 2 | `channel_mean` | 0.037 | 0.68 | 0.10 |
| 50 | 1 | `none` | 0.043 | 0.83 | 0.44 |
| 50 | 1 | `channel_mean` | 0.043 | 0.83 | 0.43 |
| 50 | 2 | `none` | 0.037 | 0.68 | 0.09 |
| 50 | 2 | `channel_mean` | 0.037 | 0.68 | 0.09 |
| 50 | — | `no_pca` | 50.1 | 51.0 | 188 |

- オフセットが大きいと、`none` の第1成分はほぼ平均スペクトルそのものになり、`none` と `channel_mean` の結果はほとんど同じになります。`none` を選んでも輝線の削れは避けられません。
- オフセットがあると `no_pca` ではオフセットがそのまま残るので、何らかの除去が必要です。
- 成分数を増やすと輝線なし領域の残差は熱雑音の水準まで下がりますが、輝線の損失も大きくなります。残差 RMS だけで成分数を選ぶと輝線を失います。
- 大気の形を空の周波数に固定したため、窓をずらすと `offset_k × slope_frac × (シフト量 / 帯域の半幅)` の共通成分がシフト量に同期して現れます。オフセット 50 K・既定の傾きと変調幅では最大 ±0.37 K で、大気成分は厳密には2成分(ランク2)になります。

以上は単純な PCA 除去の性質を示したもので、輝線の損失を抑える方法(輝線モデルを先に引いてから PCA を繰り返すなど)は段階1では実装していません。

輝線幅を変える場合は `--set source.line_fwhm_kms=100` のように指定します。輝線が太いほど輝線の損失は増えます。

### 処理の概要と記号の定義

本段階①は、アンテナ駆動を行わず天球上の同一位置を見続け、LO周波数のみを変調する「1ビーム・1点観測（固定点観測）」を対象としています（森脇氏の助言に合致）。
すべての TOD 配列は同一の時間×分光器チャンネル座標 `(n_time, n_channels)` [K] で扱われます。

- $X$: 元の模擬観測 TOD
- $A_r$: $r$ 回目で推定した天体信号 TOD ($A_0 = 0$)
- $C_r$: $r$ 回目で推定した相関成分 TOD (PCA 除去成分。チャンネル平均を含むのは `mean_mode: channel_mean` の場合)
- $E_r$: $r$ 回目の残差 TOD ($E_r = X - C_r - A_r$)

各回 $r=1, 2$ の手順:
1. $U_r = X - A_{r-1}$ ($U_1 = X$, $U_2 = X - A_1$)
2. $U_r$ に PCA を適用して相関成分 $C_r$ を推定
3. $X - C_r$ を復調・時間平均し、天体スペクトルモデル $\tilde{s}^\mathrm{model}_r$ を推定
4. $\tilde{s}^\mathrm{model}_r$ を FMLO シフトで再変調し、天体信号 TOD $A_r$ を作成
5. $E_r = X - C_r - A_r$ を算出

数学的恒等式 $X = C_r + A_r + E_r$ がマシンイプシロン水準 ($< 10^{-14}$ K) で厳密に成り立ちます。

### 実装上の選択・省略事項の整理

- **チャンネル数と解析時ビニングの扱い**:
  論文 §4.2 では SAM45 分光計の取得時チャンネル数として 4096 ch（帯域 2000 MHz）が使用され、オフライン解析時（§4.3）に計算時間短縮のため 2チャンネル平均（ビニング）により 2048 ch に縮約されています。本シミュレーションコードは取得時チャンネル数である 4096 ch を維持しており、解析時の 2チャンネルビニングは実施していません（取得時仕様とは一致、整約処理としては差分）。
- **PCA 平均処理の前提と実装の区別**:
  論文 §2.5 では PCA を適用する前提として「各チャンネルの時間平均値が差し引かれていること（“mean values are assumed to be subtracted”）」が明記されています。一方、PCA による低ランク再構成 $\bX\msp{c} \simeq \bP_{:,:K} \,@\, \bC_{:K,:}$ 後に、差し引いた平均値を相関成分に含めるか、信号側へ戻すかについては論文中に明示的な記述がありません。本実装では、原点まわり SVD により平均除去を行わない `mean_mode: none`（既定）と、チャンネル平均を差し引いて戻さない `mean_mode: channel_mean` を選択可能としています。
- **実効半幅の離散性**:
  `half_width_ch = 150`, `zigzag_step_ch = 20` の場合、三角波生成式 $pos = t \cdot step$, $shift = a - |(pos + a) \bmod 4a - 2a|$ により、実際の最大・最小シフト量は $\pm 140$ ch となります（$\pm 150$ ch には到達せず 140 ch で折り返す）。設定半幅（150 ch）と実効半幅（140 ch）は区別して記録されています。
- **反復回数の固定**:
  論文の収束反復（Frobenius ノルム判定）は実装せず、$r=1, 2$ の 2回固定としています。2回目で必ず改善・完全復元すると仮定せず、変化（改善または悪化）を客観的に記録します。
- **サイドバンドモデル**:
  本シミュレーションは「イメージ側の天体輝線・大気輝線を省略した簡易モデル」として扱っており、受信機の 1SB 化や $R=0$ と同一視するものではありません。
- **雑音水準の推定方法**:
  全時刻観測された領域 ($hits == n_\mathrm{time}$) の有限値から中央値絶対偏差 (MAD) により基本雑音水準 $\sigma_0$ を求め、ヒット数補正 $\sigma_d = \sigma_0 \sqrt{n_\mathrm{time} / hits_d}$ を適用するシミュレーション用の簡易推定法です。論文の重み付き分散推定と同一ではありません。

### パラメータの出どころ

論文本文は Fig. 6 の模擬条件を数値で示していません(§3.2 の図説明は「zig-zag FM で観測した模擬 timestream、帯域中央付近に強い輝線」のみ)。著者の FMFlow にも図の生成コードはありません。そこで、arXiv:1911.02574 のソースに含まれる `flowchart.pdf` の埋め込みパネル画像(720×720 画素)を数値に戻してパラメータを決めました。各値の区分は `config/taniguchi2020_fig6.yaml` に書いてあります。

| 区分 | 項目 |
|---|---|
| 図から一意に読める | 時間サンプル数 100、zig-zag の形(0…24…0、折り返し点が 2 サンプル続く、周期 50 サンプル、開始位置)、反復 2 回 |
| 図から測定(誤差あり) | 輝線(ガウシアン、ピーク 5.0、FWHM 36.5 ch)、FM step、相関成分(全チャンネル共通の時間変動。`data/taniguchi2020_fig6_correlated_profile.csv`)、雑音の大きさ、カラーレンジ |
| 論文・FMFlow v0.2.7 の記述 | θ_cutoff = 5、PCA は時間平均を引いて行い平均を戻す、スペクトルの雑音 = 標準偏差/√n |
| 仮定・当てはめ | チャンネル数 2048(図からは 720 より多いとしか分からない。§4.3 の値)、PCA 成分数 K = 4(1 回目)/ 1(2 回目)、乱数 seed |

注意点:

- **強度の単位**は「論文図の E^nc パネルの標準偏差」です。図はカラーレンジ下限で頭打ちになっているため、頭打ち前の雑音の標準偏差はこの単位で 1.06 になります(`noise.sigma`)。
- **K は反復ごとに違う値**です。同じ K を両方に使うと、1 回目(輝線の取りこぼし量)と 2 回目(T^cor に輝線がほぼ残らない)を同時には合わせられませんでした。論文にこの記述はなく、図への当てはめの結果です。
- **σ-cutoff は片側判定**(s/σ > θ)です。論文の式は |s| ですが、図の T^ast には負値が無く、FMFlow の実装(片側)と整合します。`--set reduction.two_sided_cutoff=true` で論文式に切り替えられます。
- **FM step は整数チャンネルに丸めています**(測定値 23.24 ch → 23 ch)。このため輝線位置は論文図と最大 2.4 画素(パネル幅 720 画素)ずれます。
- **雑音の乱数列は復元できない**ので、雑音の模様は論文図と一致しません。
- 論文図右下の凡例(flow of estimation / matrix operation)は描いていません。

### 論文図との数値比較

## 外部入力キューブの固定点模擬観測(試作)

RA 方向 × Dec 方向 × 周波数の天球キューブを外部から与え、1 ビーム・固定点で模擬観測する。
キューブの生成と観測処理を分離してあり、内部生成のガウシアンキューブも外部入力キューブも
同じ `fmlo_sim.observation.observe()` を通る(`pipeline.simulate()` はその互換ラッパー)。

天球キューブ(RA × Dec × 周波数)と、固定点で生成する観測時系列(時間 × 分光器チャンネル)は
別のデータである。

### 実行方法

生成(A)と解析(B)は別々に実行できる。既存の一括実行(`run_step1.py`、`run_fig6.py`)もそのまま使える。

```bash
# A. キューブ + 観測設定 → 模擬観測データを保存(解析はしない)
python run_observe_cube.py --cube outputs/step1/cube.npz \
    --set pointing.ra_arcsec=0 --set pointing.dec_arcsec=0 \
    --out outputs/observe_demo/observation.npz

# B. 保存した観測データ → 解析・評価
python run_analyze_observation.py --obs outputs/observe_demo/observation.npz \
    --outdir outputs/observe_demo/analysis --line-from-source --two-step
```

- 入力キューブは `cube.save_cube` の形式(`run_step1.py` が出力する `cube.npz` と同じ)。
  自作のキューブは `cube.save_cube(path, cube, ra, dec, freq)` で保存できる。
- 観測設定は既存の YAML と同じ書式。使うのは `seed` / `pointing` / `spectrometer` / `modulation` /
  `observation` / `noise` で、`source` / `cube` / `removal` / `evaluation` は置いてあっても A では使わない
  (使わなかったセクションは出力に記録する)。`pointing` は数値で指定する(`null` はエラー)。
- `--internal` を付けると、設定からガウシアンキューブを内部生成して同じ形式で保存する。
- B の解析条件は設定 YAML の `removal` / `evaluation` から読む。評価に使う輝線領域は
  `--line-from-source`(キューブに記録されたガウシアン天体の生成条件を使う)か
  `--line-window-ghz LO HI --ref-freq-ghz F`(周波数窓を明示)で与える。
  どちらも指定しなければ、輝線領域に依る評価値は「未計算」と理由を記録し、全域の残差だけを出す。
- 既存の出力ファイルは上書きしない(`--overwrite` を付けた場合だけ上書き)。

### 対応する入力と、エラーになる条件

| 項目 | 対応する条件 | 対応外(エラー) |
|---|---|---|
| 値 | 単位 K、有限値の実数配列 | NaN / inf、マスク付き配列、複素数 |
| 軸順序 | `cube[i_ra, i_dec, i_freq]` | それ以外(軸の長さと配列の形が合わない場合を含む) |
| 空間軸 | 角度オフセット [arcsec]、昇順・等間隔 | 降順、不等間隔、FITS / WCS |
| 周波数軸 | [GHz]、昇順・等間隔、チャンネル幅が分光器と同じで、分光器のチャンネルに重なる | 降順、不等間隔、幅の不一致、半端なずれ |
| 周波数範囲 | 変調後の全観測窓がキューブの範囲に収まる | 1 ch でも不足する場合(外挿・循環シフト・ゼロ埋めはしない) |
| 指向位置 | 端の画素中心 ± 半画素まで。最近傍画素を使う | マップ外(端の画素へ丸めない) |

- 周波数軸はキューブのものをそのまま使い、作り直さない。
- 等間隔・格子の一致の判定は、間隔の 1e-6 倍まで。float64 の周波数軸の丸め誤差(約 6e-11 ch)は通り、
  float32 の周波数軸(約 0.03 ch の誤差)は通らない。
- 2 つの画素のちょうど中間を指した場合は、番号の小さい画素になる(既存の `extract_spectrum` の仕様)。
- ビーム畳み込み、空間補間、スキャン、マルチビームには対応していない。

### 保存される内容

`observation.npz`(A の出力)。浮動小数の配列はすべて float64 のまま保存する(丸めなし)。
このため再読込した配列は保存前とビット単位で一致し、再読込後の解析結果も直接解析した結果と一致する
(テストでは厳密一致で比べている)。既定設定(600 × 4096)で約 80 MB になる。

| 配列 | 内容 |
|---|---|
| `observed` | 合成した観測時系列 [K] (時間 × チャンネル) |
| `signal_tod` | 天体信号のみの観測時系列 [K](正解情報) |
| `noise_thermal`, `noise_atmosphere` | 各雑音成分 [K](正解情報。有効にした成分だけ) |
| `truth_k` | 観測した画素の正解スペクトル [K](キューブの周波数軸上) |
| `time_s`, `shifts_ch`, `window_start_index` | 時刻 [s]、シフト量 [ch]、各時刻の窓の先頭インデックス |
| `freq_wide_ghz`, `cube_ra_arcsec`, `cube_dec_arcsec` | キューブの座標軸 |
| `meta`(JSON) | 単位・軸の意味・周波数対応、キューブの識別情報(パス・SHA-256・形・型)、指向位置と画素、使った設定と seed、コードのコミットと変更状態、実行環境 |

時刻 t・チャンネル c の空の周波数は `freq_wide_ghz[window_start_index[t] + c]`。
取得できなかった情報(git が使えない場合など)は `null` と理由を記録する。

`analysis.npz` と `metrics.json`(B の出力)には、復元スペクトル・ヒット数、解析条件、評価結果、
観測データの識別情報(パス・SHA-256)を保存する。

正解情報(`truth_k`、`signal_tod`、`noise_*`)は観測データと同じファイルに入っているが、
`obsio.load_observation()` は観測データと正解情報を別々のオブジェクトで返し、
推定(`analysis.analyze()`)には観測データだけを渡す。正解を参照するのは評価(`analysis.evaluate()`)だけである。

### 既存の 3 経路との関係

設定も解析仕様も異なるので、統合はしていない。

| 経路 | 入力 | 解析 |

### 検証

`tests/test_observe_cube.py`(外部キューブ)と `tests/test_regression_baselines.py`(既存 3 経路の基準値)で確認している。

- 内部生成キューブを直接観測した結果と、保存・再読込して観測した結果が一致する(厳密一致)。
- 位置ごとに異なるスペクトルを持つ非ガウシアンの小さなキューブで、指定した画素のスペクトルが観測される。
- 雑音なし・除去なしでは、観測された周波数の復元値が入力に一致し、未観測の周波数は NaN(ヒット数 0)になる。
  float32 のキューブは厳密一致、float64 のキューブは相対誤差 `n_time × 2.2e-16` 以内
  (同じ値を `n_time` 回足して割る計算の丸め)。
- 雑音なし / 熱雑音のみ / 大気のみ / 両方で、成分の和が観測時系列に厳密に一致する。
- 保存 → 再読込 → 解析の結果が、直接解析した結果と一致する(NaN の位置・ヒット数・軸を含む)。
- 形の不一致、非対応の軸、非有限値、マップ外、周波数帯域不足がエラーになる。
- 入力キューブと観測時系列が変更されない。正解情報を壊しても推定結果が変わらない。
- 既存 3 経路の基準値(コミット 91c0c9c で採取)が rtol 1e-9 で再現する。

テストが通ることは「変更前と同じ結果が出る」「入出力が整合している」ことの確認であり、
モデルや解析が研究上正しいことの保証ではない。

### 互換性

- `pipeline.simulate()`、`pipeline.reduce()`、`evaluation.evaluate()` の引数と戻り値は変わらない。
- 指向位置がマップ外のとき、以前は端の画素に丸められていたが、エラーになる(`run_step1.py` も同じ)。
- `evaluation.evaluate()` は、輝線のない領域が 1 チャンネルも無い・正解の積分強度が 0 などで
  評価値が定義できない場合に `None` を返す(以前は NaN または例外)。

### マイルストーン1:雑音モデルと PSD 評価

- **`random_walk`**:正規乱数の累積和。平均 0・標準偏差 `rms_k` に規格化(PSD はおおむね f^-2)。
- **`external`**(GATO など外部シミュレータの出力):`.npy` または `.npz`(配列名 `atmosphere`)。形は次の2通りだけ受け付け、
  それ以外はエラーにする(補間・切り詰めはしない)。
  - `(n_time,)`:全チャンネル共通の時間変動 a(t)。`(offset_k + a(t)) × s(ν)` に使う
  - `(n_time, n_wide)`:空の周波数ごとの大気の明るさ [K]。天体と同じ観測窓で切り出す(`offset_k` と `slope_frac` は使わない)。
    `.npz` に `freq_ghz` があれば広い周波数グリッドと一致するか確かめる。スキャンでは `atmosphere_x_scan` のようにパス名付きの配列があればそれを使う
- **装置雑音**:全チャンネル共通の 1/f^α 利得変動。チャンネル(IF)に固定されるので、窓で切り出さずにそのまま足す。
- **PSD の評価**(`evaluation.psd_comparison`):輝線が一度も入らないチャンネルについて、除去前後の PSD を理論的な熱雑音レベル
  2σ²Δt(σ = Tsys/√(Δν_ch Δt))と比べ、低周波域(既定 0.1 Hz 未満)の PSD / 熱雑音 の比を出す。
  `run_step1.py` は `fig11_psd_vs_thermal.png` と `metrics.json` の `psd_excess_over_thermal` に出力する。

既定設定(大気は層流、オフセット 0)での低周波域の比:除去前 68.5 → PCA 後 0.90(チャンネルごとの PSD の平均)。
チャンネル平均した時系列(共通モード)の PSD は PCA 後に熱雑音レベルの 0.1 倍まで下がる。PCA の成分が共通モードの
熱雑音まで取り除いているためで、相関雑音が残っていないことの確認にはなるが、白色レベルとの一致は期待できない。

### マイルストーン2:反復 PCA と輝線幅スイープ(段階 2-A)

**反復 PCA**(`removal.iterative_pca`、Taniguchi et al. 2020 §3.2 の反復):

1. i = 1:C⁽¹⁾ = PCA(X)。X − C⁽¹⁾ を復調・時間平均し、σ-cutoff した輝線モデルを再変調して A⁽¹⁾ とする
2. i > 1:C⁽ⁱ⁾ = PCA(X − A⁽ⁱ⁻¹⁾)、A⁽ⁱ⁾ = モデル(X − C⁽ⁱ⁾)
3. ‖A⁽ⁱ⁾ − A⁽ⁱ⁻¹⁾‖_F / ‖A⁽ⁱ⁾‖_F < `tol` か `max_iter` で終了。復元には X − C(最終回)を使う

モデルを作る部分は関数として渡すので、1 点観測(復調 → σ-cutoff → 再変調)とスキャン(グリッディング → σ-cutoff → 逆投影)で
同じ反復を使っている。σ-cutoff は既存の `iterative.make_noise_free_model`(両側 |s| 判定、MAD による雑音推定)をそのまま使う。

**注意**:輝線が 1 チャンネルも検出されないと A = 0 のまま 2 回目で「収束」と判定される。反復は何もしていないので、
`final_model_norm_k`(最終回の ‖A‖_F)が 0 かどうかで見分けること。

**復調の重みマスク**:`modulation.demodulate_tod()` は、空の周波数に戻した時系列 (n_time, n_wide)(観測していない周波数は NaN)と
有効サンプルの重みマスク W^NaN(1 / 0)を返す。重み付き時間平均は既存の `demodulate()` と一致する(テストあり)。

**cycle jitter**:zigzag の最小周期ごとに [−floor(step/2), +floor(step/2)] の整数オフセットを足す。周波数グリッドはその分だけ広げる
(`ModulationConfig.max_abs_shift_ch`)。random パターンとの組み合わせはエラー。

**スイープの結果**(`config/step2_sweep.yaml`:大気 colored α = 1.5・オフセット 50 K、K = 3、mean_mode none、cycle jitter あり、
seed = 20261005。全条件で熱雑音・大気の乱数列は同じ):

| FWHM [km/s] | 半幅 [ch] | FWHM / 変調全幅 | 方法 | 積分強度比 | ピーク比 | 輝線なし領域の残差 RMS [K] | 反復回数 |
|---|---|---|---|---|---|---|---|
| 50 | 300 | 0.085 | simple_pca | 0.29 | 0.78 | 0.041 | 1 |
| 50 | 300 | 0.085 | iterative_pca | 0.98 | 1.01 | 0.037 | 5 |
| 50 | 150 | 0.17 | simple_pca | −0.03 | 0.51 | 0.037 | 1 |
| 50 | 150 | 0.17 | iterative_pca | 0.94 | 0.97 | 0.037 | 7 |
| 100 | 300 | 0.17 | iterative_pca | 0.93 | 1.00 | 0.037 | 9 |
| 100 | 150 | 0.34 | iterative_pca | 0.88 | 0.94 | 0.037 | 19 |
| 200 | 300 | 0.34 | iterative_pca | 0.35 | 0.58 | 0.036 | 20(未収束) |
| 200 | 150 | 0.68 | iterative_pca | 0.003 | 0.03 | 0.037 | 2(A = 0) |

- オフセット 50 K・K = 3 では、simple_pca は輝線をほぼ消す(段階1の「オフセットと平均モード」の節と同じ理由)。
- iterative_pca は FWHM / 変調全幅 ≲ 0.2 で 9 割以上を戻す。比が 0.35 付近から反復が遅くなり(20 回で未収束)、
  0.68(輝線幅 205 ch > 変調全幅 300 ch)では 1 回目の PCA が輝線をほぼ吸い、検出できる輝線が残らないので回復しない。
- 輝線なし領域の残差 RMS は、どの条件でも熱雑音の水準(0.037 K)とほとんど変わらない。**残差 RMS だけでは輝線の損失は分からない**。

### マイルストーン3:1 ビーム OTF + FMLO スキャン(段階 2-B)

**処理の流れ**(`run_step2_scan.py`):

| 手順 | 内容 | 関数 |
|---|---|---|
| 1 | 正解キューブを作り、ガウシアンビームで空間方向に畳み込む(面積 1 に規格化、マップの外は 0 K) | `cube.convolve_beam` |
| 2 | スキャン軌跡 (RA(t), Dec(t)) を Δt ごとに作る | `scan.make_passes` |
| 3 | 各時刻の位置でキューブをバイリニア補間し、その時刻のシフト量の窓を切り出す(np.roll なし) | `scan.observe_pass` |
| 4 | 雑音を足す(段階1と同じ関数。パスごとに独立な乱数) | `noise.make_noise_components` |
| 5 | 雑音除去(simple_pca / iterative_pca)。パスごとに行う | `mapping.reduce_passes` |
| 6 | 復調し、ガウシアンカーネルの重み付き平均で出力キューブ (RA × Dec × 周波数) にグリッディング | `mapping.grid_tod` |
| 7 | x_scan と y_scan を basket weave で統合 | `mapping.combine_weighted_mean` / `combine_fourier` |
| 8 | 評価・図 | `evaluation.evaluate_scan_cube` |

- **スキャンの形**:`single_point` / `x_scan`(RA 方向に往復し、行ごとに Dec を `row_spacing` 進める)/ `y_scan` / `basket_weave`(x と y の2パス)。
  1 行のサンプル数は round(L / (v Δt)) + 1。**行の折り返しは瞬時**(加減速・ランプ区間・OFF 点なし)で、行のあいだも連続にサンプリングする。
- **グリッディング**:T(p, ν) = Σ_t w(p,t) W(t,ν) d(t,ν) / Σ_t w(p,t) W(t,ν)。w はカーネル exp(−r²/2σ²)(`kernel_support_fwhm` × FWHM で打ち切り)、
  W は復調の重みマスク。分子と分母を別々に持つので、重み付き平均の basket weave は分子・分母の和になる。
- **逆投影**:キューブを軌跡に沿ってバイリニア補間し、各時刻の窓を切り出す(反復 PCA の A⁽ⁱ⁾)。
- **スキャンの σ-cutoff**:1 サンプルの雑音 σ_t を X − C の MAD から見積もり、ボクセルの雑音を σ_t √(Σw²) / Σw とする。
- **フーリエ空間の basket weave**(`fourier`):x_scan の走査方向の雑音(行ごとのオフセットなど)は k_RA ≈ 0 に集まるので、
  w_x = k_RA² / |k|²、w_y = k_Dec² / |k|² で足す(w_x + w_y = 1 なので共通の構造は保たれる)。マップを周期的とみなすので端で歪みうる。
- **評価の基準**:正解キューブそのものではなく、**天体信号だけの時系列を同じ手順でグリッディングしたキューブ**(reference)と比べる。
  グリッディングの平滑化(ビーム ⊗ カーネル)は基準にも同じだけ入るので、残差は雑音と雑音除去による誤差だけになる。
  正解(ビーム畳み込み済み)を出力グリッドに補間したもの(truth)との比較も併記する。評価はスキャン領域の内側の画素、
  全サンプルで観測された周波数だけで行う。

- 1 点観測と違い、スキャンでは 1 ボクセルの S/N が低い(1 パス・1 画素の雑音 約 0.19 K)。σ-cutoff をボクセルごとに 5σ で行うと、
  広がった天体の裾が輝線モデルから落ちる。オフセットのある大気では第1主成分がほぼ時間平均スペクトルになるので、
  モデルに入らなかった輝線の**時間平均**(マップ全体に薄く広がった成分)は PCA に吸われ続け、反復しても戻らない。
- そこで判定の前に周波数方向に平滑化する `removal.model_smooth_ch` を加えた(既定 1 = なし。1 点観測には影響しない)。
- 成分数 K は、この大気モデル(平坦 × 時間変動 + 変調で動く傾き)が実質ランク 2 なので 2 にした。K = 3 では 3 番目の成分が輝線を吸い、
  200″ 四方の試行でフラックス復元率が 0.80 → 0.68 に下がった。

**未実装・簡略化**:行の折り返し(ランプ区間)と OFF 点、仰角・位置に依存する大気、x と y を同時に使った反復の評価
(`--joint-basket-weave` で実行はできるが、上の表には含めていない)、全帯域 4096 ch での実行(計算量のため 1024 ch にしている)。

## 段階①の成果・相談事項・Issue #5 更新案 (段階②への引き継ぎ)

### 1. 段階①で再現・確認できた性質と数値

1. **数学的恒等式の厳密成立**:
   $X = C_r + A_r + E_r$ がマシンイプシロン水準 ($< 10^{-14}$ K) で厳密に成立し、コードの加減算・成分分割に不整合がないことを確認。
2. **天体信号吸収と反復による改善**:
   - 同一条件（step=20 ch）内での反復効果:
     - 1回目推定 ($r=1$): PCA が天体信号の一部を大気変動として誤吸収し、復元輝線のピーク比が 0.9922、積分強度比が 0.9445 に減衰。残差 RMS は 0.0786 K。
     - 2回目推定 ($r=2$): 1回目の天体信号モデルを差し引いた $U_2 = X - A_1$ に対して PCA を再実行することで天体信号の誤吸収が抑制され、ピーク比 1.0067、積分強度比 0.9976、残差 RMS 0.0364 K へと、1回目から明確に改善。
3. **条件間（step=10 ch vs step=20 ch）の比較と留意点**:
   - 2回目推定同士の比較:
     - step=10 ch: ピーク比 0.9997 (絶対誤差 0.0003), 積分強度比 0.9947, 残差 RMS 0.0373 K
     - step=20 ch: ピーク比 1.0067 (絶対誤差 0.0067), 積分強度比 0.9976, 残差 RMS 0.0364 K
     - 積分強度比や残差 RMS は step=20 ch の方がわずかに改善している一方、ピーク比の誤差は step=10 ch の方が小さく、step=20 ch が全指標で一律に優れているわけではありません。
   - 複合変化の因果関係:
     - ステップ幅の変更（10 → 20 ch）に伴い、離散三角波の折り返し位置（実効半幅 ±150 ch → ±140 ch）および変調周期（60 サンプル / 6.0 秒 → 30 サンプル / 3.0 秒、60秒間の往復回数 10往復 → 20往復）も同時に変化しています。したがって、数値の差異をステップ幅単独の因果効果と断定することはできません。
   - 熱雑音水準との関係:
     - 2回目の残差 RMS（0.0364 K）は熱雑音理論限界期待値（0.037 K）と同等の水準に達していますが、これは「残差の大きさ（RMS）が熱雑音水準と同等である」ことを示す指標であり、「相関成分や系統誤差が完全に取り除かれて熱雑音だけが残ったことが厳密に確認された」ことを意味するものではありません（周波数方向・時間方向の微小な系統歪みや相関の残存可能性は排除されません）。
4. **診断図および重ね描きプロットの確立**:
   Taniguchi et al. (2020) Fig. 6 に対応する 2行×4列診断図（全帯域版・輝線拡大版）および復元スペクトル・残差の重ね描き図（fig10）の生成パイプラインを確立。
